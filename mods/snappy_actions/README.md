# Snappy Actions（跟手动作）

纯客户端延迟补偿优化 mod：让"按空格捡东西"**立即开始**且**平滑收尾**，并提前解除游戏写死的
**0.5 秒重复冷却**。单击更利索，连捡不断节奏。

## 解决什么问题

开启游戏"延迟补偿"后，按下空格：弯腰动画立即播放（预测），但人物会**僵在弯腰姿势**约 0.25~0.4 秒
（等服务端状态快照确认），然后**硬切**回站姿；物品还要再等一跳快照才消失；连续捡东西每下之间还要
额外吃 0.5 秒写死的重复冷却。详见笔记《饥荒联机版延迟补偿：按一下空格，到底发生了什么》。

## 做法

- **首按进时间线**：每个动作在发出请求时建立条目，在"预测的服务端完成时刻"本地收尾——补播
  `pickup_pst` 平滑起身并回到 idle，不再等快照、不再硬切。
- **收尾视觉 = 原版完成方式**：提前收尾时调用 `FlattenMovementPrediction` 提交预测位移缓冲（跳过它会导致
  缓冲累积、引擎强制落账时的周期性"卡一下"），并让 `pickup_lag` 完整弧线自然续播到站立帧。
- **收尾时机两档**：
  - 保守：`发送 + 实测基线`（基线 = 最近观测到的"请求→服务端开始"最快延迟，≈原版确认时刻的中位数，
    但不依赖快照准时）；
  - 激进：把等待**钳制**在零延迟理想网络的物理下限（执行点 6 帧 + tick 1 帧 ≈ 233ms）。160ms ping
    下与保守档几乎一样（基线已低于下限），**200ms+ 高 ping 才有感**；更快必错，会 100% 回滚。
- **提前解除 0.5s 冷却**：本地收尾即清 `remote_controls[CONTROL_ACTION]`，下一次空格立刻能被受理。
- **连拍节奏（0.2.0 重做）**：区分两种输入——
  **主动新按**（松开后再次按下）：只等服务端能受理（`FreeAt`）就发，不受 0.5s 节流；
  **按住重复**：必须满"按住连拍间隔"（默认 0.5s = 原版重复冷却，防误触；可调 0.35s 快速档）。
  链式成员进一步改用 **LeftClick RPC 发送**（点击点校验通过时）：服务端第 6 帧解除 busy 即受理，
  比空格通道早 4 帧——这是 BLC "1.6x" 速度的来源。
- **验证与回滚**：每个在途请求监听服务端状态变化来确认；超时未见（雷劈/被打断/请求被拒）→ 把隐藏的
  物品放回、退回原版行为 3 秒、余量 +1 帧（上限 +4，连续顺利后逐步退还）。
- **捡物品预测隐藏**：`PICKUP` 类目标在本地收尾时先 `Hide()`，等快照真实移除；回滚时 `Show()`。

## 明确不做的

- **草/树枝等长动作**（`dolongaction`）：同样享受提前解除冷却与平滑起身，但**不做物品隐藏**——
  "已采"外观由快照驱动，无法伪造；其服务端时长按近期观测（缺省 30 帧）估算，只影响连拍节奏。
- **战斗/攻击**：不碰。完美方案等于在客户端模拟一个服务端，投入产出比极差。
- **背包栏即时更新**：物品"真进背包"由快照驱动，属于快照地板，不改。

## 与 Better Lag Compensation 的关系

功能重叠，**二选一**。本 mod 专注"首按也预测"（BLC 刻意锚定首按、单击零收益）与"拆除 0.5s 冷却"，
链式调度比 BLC 简化（无 LeftClick 早发、无 Woodie 快采分支）。检测到 BLC 已加载时本 mod 自动让位。

## 配置

| 选项 | 默认 | 说明 |
|---|---|---|
| 收尾时机 | 保守 | 保守 / 激进 / 关闭 |
| 按住连拍间隔 | 原版 0.5s | 快速 0.35s 时按住扫场明显更快，代价是按住稍长就会多捡下一个（单击永远只捡一个） |
| 安全余量 | 1 帧 | 收尾与连拍调度的额外帧数，抖动网络可 +1 |
| 日志 | 开 | `client_log.txt` 输出回滚等异常与每分钟小结 |
| 开关热键 | 无 | F8~F12 游戏内临时开关（轮询检测，头顶出字提示），用于和原版对比 |

## 开发

- 部署：游戏 mods 目录中的 `snappy_actions` 是指向本目录的 Junction（`mklink /J`），改完即生效。
- 语法校验：本机无 lua/luac，用 `pip install luaparser` + `luaparser.ast.parse` 逐文件检查。
- 结构：`modmain.lua`（沙箱白名单，只做装配）→ `scripts/snappy/{util,session,actions,main}.lua`
  （require 后运行在游戏全局环境）。
- 已知边界：控制器按键不走 `DoActionButton` 的推迟队列（退化为原版节奏）；服务器强卡顿
  （`cancelmovementprediction`）时在途请求按"被原谅"处理，不做惩罚。
- 与动作/操作类 mod（ActionQueue RB3、Lazy Controls、小恶魔操作优化等）共存：实测某 mod 会让
  `wilson_client` 状态图的 `server_states` 变为 nil，原版 `ServerStateMatches` 不判空会直接报错
  崩到 Insight。0.1.1 起本 mod 对这两个状态**不再回落原版 onupdate**，改为安全复刻原版分支
  （判空后比对确认），并在检测到该异常时输出一次性日志。
